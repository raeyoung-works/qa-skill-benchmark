# 용어집

[프로젝트 정리](../README.md) · [심화](deep-dive.md) · **용어집**

> 프로젝트 정리와 심화에 나오는 용어를 모았다. 괄호 안은 영문이나 업계에서 쓰는 이름이다.

---

## 1. 배경

| 용어 | 뜻 |
|---|---|
| EYWA | AX 프로젝트 팀의 첫 프로젝트 이름. 영화 〈아바타〉에서 모든 생명을 이어 주는 나무의 이름에서 따왔고, 백엔드·프런트엔드·QA를 잇는다는 뜻이다 |
| AX 프로젝트 팀 | 직군별 조직(챕터)에서 선정된 팀원으로 꾸린, AI를 업무에 적용하는 팀 |
| 챕터 | 같은 직군(백엔드, 프런트엔드, QA 등)끼리 묶인 조직 |
| 트랙 | 직군별로 나눈 측정 갈래. 이 문서는 QA 트랙을 다룬다 |
| 리드타임 (lead time) | 일을 시작해서 끝낼 때까지 걸리는 시간. 이 프로젝트가 줄이려는 값이다 |

## 2. QA 업무

| 용어 | 뜻 |
|---|---|
| QA (Quality Assurance) | 새 기능이 출시 전에 기획대로 동작하는지 확인하는 일 |
| 기획서 (PRD) | 기능이 어떻게 동작해야 하는지 적은 문서. 이 측정에서는 맞는 동작의 유일한 기준이다 |
| 결함 (버그) | 기획서와 다르게 동작하는 부분 |
| 테스트케이스 (TC) | "이렇게 하면 이런 결과가 나와야 한다"를 적은 확인 항목 |
| 자동 테스트 (E2E) | 사용자가 하는 동작을 프로그램이 브라우저에서 처음부터 끝까지 그대로 재현하는 테스트 |
| 시험용 서버 | 출시 전 기능을 올려 두고 시험하는 서버. 이 측정에서는 결함 5개를 일부러 심어 두었다 |
| 회귀 검증 | 변경 후에 원래 되던 기능이 그대로 되는지 다시 확인하는 것 |
| 거짓 통과 (false pass) | 결함이 있는데도 테스트가 통과하는 것. 테스트가 실제로는 아무것도 확인하지 않을 때 생긴다 |
| 오탐 (false positive) | 결함이 아닌 것을 결함으로 보고하는 것 |
| 근본 원인 분석 | 겉으로 드러난 증상이 아니라, 그 증상을 만든 원인을 거슬러 찾는 것 |
| 린트 규칙 | 코드를 실행하기 전에 정해 둔 금지 패턴이 있는지 자동으로 검사하는 규칙 |
| 병목 | 전체 시간 중 가장 많은 시간을 차지해 전체 속도를 결정하는 단계 |
| 성능 회귀 | 변경 후에 이전보다 느려지거나 결과가 나빠지는 것 |

## 3. AI 도구

| 용어 | 뜻 |
|---|---|
| Claude Code | AI가 파일을 읽고 쓰고 명령을 실행하며 업무를 하는 도구. 이 측정에서 AI가 일하는 환경이다 |
| 모델 (Opus 4.8, Opus 5.5) | AI의 버전. 같은 도구라도 모델이 다르면 결과가 달라진다 |
| 스킬 (skill) | AI에게 주는 업무 절차와 규칙 묶음. 이 프로젝트가 효과를 재려는 대상이다 |
| Playwright | 브라우저를 프로그램으로 조작하는 테스트 도구. 자동 테스트를 만들고 실행하는 데 쓴다 |

## 4. 측정

| 용어 | 뜻 |
|---|---|
| 벤치마크 (benchmark) | 같은 조건에서 반복해 재고 비교하려고 만든 측정 틀 |
| 사람 기록 | 같은 기획서로 사람이 직접 테스트케이스를 쓰고 수행한 시간. 모든 비교의 출발점이다 |
| 비교 기준 (기준선, baseline) | 이후 측정과 비교하는 출발점으로 정한 측정 |
| 통제 변수 | 결과에 영향을 줄 수 있어서 모든 측정에서 똑같이 맞춘 조건. 이 측정에서는 스킬 말고 모두 고정했다 |
| 사전 등록 | 결과를 보기 전에 지표와 판정 기준을 문서로 정해 두는 것 |
| 파일럿 | 본 판정 전에 작은 규모로 해 보는 측정. 측정용 문제가 1개뿐이라 이번 결과를 파일럿으로 보고했다 |
| 탐지율 | 심어 둔 결함 중 찾은 비율. 5개 중 5개를 찾으면 100%다 |
| 정확도 | AI의 보고 중 심어 둔 결함과 맞은 비율. 보고가 많을수록 내려가기 쉽다 |
| 전체 경과 시간 | 일을 시작한 시각부터 끝낸 시각까지의 실제 시간. 사람 기록의 대표값으로 썼다 |

## 5. 이 프로젝트에서 쓰는 말

| 용어 | 뜻 |
|---|---|
| 과제 | 측정용 문제 하나. 기획서, 시험용 서버, 채점용 결함 목록이 한 세트다 |
| 설정 | AI에게 어떤 스킬을 줄지 정한 것. 이 측정에서 유일하게 바꾸는 조건이다 |
| 회차 | AI가 "테스트케이스 작성 → 자동 테스트 → 결함 보고"를 한 번 도는 것. 측정 1번에 최대 3회차다 |
| 채점용 결함 목록 (정답지) | 시험용 서버에 심어 둔 결함 5개의 목록. 채점에만 쓴다 |
| 정답지 격리 | 채점용 결함 목록을 AI가 볼 수 없는 곳에 두고, 스킬을 고칠 때도 근거로 쓰지 않는 것 |
| 측정 프로그램 (하네스) | 작업 준비, AI 실행, 채점, 기록을 사람 손 없이 반복하는 프로그램 |
| 근거 확인 | AI가 실패했다고 보고한 테스트를 측정 프로그램이 직접 다시 실행해 실제로 실패하는지 확인하는 단계 |
| 채점 AI | 근거가 확인된 보고가 심어 둔 결함 중 무엇과 같은 문제인지 판단하는 AI |
| "결함이 남아 있다" 신호 | 다 찾지 못했을 때 다음 회차 전에 AI에게 알려 주는 유일한 정보. 몇 개가 남았는지는 알려 주지 않는다 |
| 오염 | 운영자의 개인 설정이나 도구가 측정에 섞여 조건이 달라진 상태 |
